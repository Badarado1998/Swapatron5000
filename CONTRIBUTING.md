# Contributing

Everyone is welcome, including people who have never used GitHub. If that is you, start with [How to have your say](docs/have-your-say.md), then take the [15 minute tour](docs/learn-github.md).

**Nothing about the box is decided yet.** The listening phase runs until Sunday, January 10, 2027. See [DECISIONS.md](DECISIONS.md) and the [timeline](ROADMAP.md).

## Ways to contribute

Everyone follows the draft [code of conduct](CODE_OF_CONDUCT.md).

- **Share a design sketch.** A photo of a pencil drawing is welcome. See [hardware/README.md](hardware/README.md).
- **Join the founding team.** Twelve small roles, and beginners are welcome. See [docs/founding-team.md](docs/founding-team.md).
- **Join a team.** Box design, electronics, box management software, or UI and UX. See the table in the [README](README.md).
- **Say why it won't work.** Doubts are welcome and are treated as challenges to overcome. See [CHALLENGES.md](CHALLENGES.md).
- **Ask for a part, or fill an ask.** See [ASKS.md](ASKS.md).
- **Add to the dream.** [VISION.md](VISION.md) is open for anyone to edit.
- **Pledge parts or supplies.** See [bom/README.md](bom/README.md).
- **Take a task.** Comment "I'll take this" on an issue. A maintainer will assign it to you.
- **Propose an idea.** Open an "Idea" issue before doing a lot of work, so others can weigh in.
- **Improve the docs.** If something confused you, fixing it is a great first pull request.
- **Help on site.** Build days and the weekly check rota are listed in [docs/maintenance.md](docs/maintenance.md).

## Points, bounties, and the Contributors Wall

Every contribution earns a line in `contributions.csv`. That one file builds the [Contributors Wall](CONTRIBUTORS.md) and the "favorite humans" top five on the README and the web page, automatically. Jobs with points attached are listed on the [bounty board](BOUNTIES.md).

Maintainers add the line when a part is received, a bounty is accepted, a pull request is merged, or a box check is logged:

```
date,username,type,description,points
2027-02-10,your-username,part,Anti-static bags,1
2027-02-14,your-username,docs,Designed the sign,2
```

Types: `part`, `build`, `code`, `docs`, `upkeep`, `idea`. Points: 1, 2, 3, or 5. Giving a part is always 1 point. If you would rather not be listed, say so and you will be left off.

## Labels

| Label | Meaning |
|---|---|
| `good first issue` | Small, well described, good for newcomers and kids |
| `bounty` | A job with points attached. See [BOUNTIES.md](BOUNTIES.md) |
| `ask` | Someone needs a part. See [ASKS.md](ASKS.md) |
| `challenge` | A reason it might not work. See [CHALLENGES.md](CHALLENGES.md) |
| `event` | An event, online or in person. See [docs/events.md](docs/events.md) |
| `decision` | An open question the community is deciding |
| `hardware` | Shell, modules, mounting |
| `electronics` | Power, lighting, sensors |
| `software` | Inventory, alerts, dashboard |
| `supplies` | Things the box uses up |
| `docs` | Guides, rules, signs |
| `needs owner` | Nobody is working on this yet |
| `rfc` | A bigger decision that needs discussion first |

## Pull requests

- Keep each pull request to one change.
- Say what you changed and why in plain words.
- Changes to the physical box at the first site need a maintainer's approval and the host's approval. See [GOVERNANCE.md](GOVERNANCE.md).

## Safety

- No designs that use mains voltage.
- Battery designs must name the chemistry, the temperature rating, and the enclosure.
- Anything with a camera or microphone must go through an `rfc` issue first.

## Be kind

Many contributors here are learning. Explain, do not scold. A code of conduct will be added before launch.
